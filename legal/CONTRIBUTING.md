# Contributing to FluidBox

Thank you for your interest in contributing to FluidBox!
We welcome improvements, bug fixes, documentation updates, and community feedback.

Please read this document carefully before submitting pull requests.

---

## 1. Code of Conduct

All contributors must follow respectful, constructive communication.  
Be kind, stay technical, and help maintain a productive environment.

---

## 2. Contributor License Agreement (CLA)

All contributors **must sign a CLA** before their pull request can be merged.

FluidBox uses **CLA Assistant** to verify this automatically.

### • Individual Contributors  
You must sign the **CLA.md** before contributing.

### • Corporate Contributors  
If contributing on behalf of a company, your organization must sign the **CCLA.md**.

You will be prompted to sign the correct agreement **when you submit a pull request**.

Your PR cannot be merged until the CLA check passes.

---

## 3. How to Contribute

### 3.1 Fork the repository
1. Click **Fork** on GitHub  
2. Clone your fork locally

### 3.2 Create a feature branch
```
git checkout -b feature/my-new-feature
```

### 3.3 Make changes  
Follow the project’s coding style and folder structure.

### 3.4 Commit changes
Write descriptive commit messages.

### 3.5 Push and open a PR  
When you submit a pull request:
- CLA Assistant will ask you to sign the CLA
- CI checks must pass
- A maintainer will review your changes

---

## 4. Coding Standards

- Use clear, consistent naming  
- Document public APIs  
- Write deterministic, testable code  
- Follow Unity best practices for performance and GC safety  
- Avoid introducing external dependencies without discussion

For major changes, please open a **discussion issue** first.

---

## 5. Reporting Bugs or Requesting Features

Use GitHub Issues and include:
- Version info  
- Platform  
- Steps to reproduce  
- Screenshots/logs if relevant
